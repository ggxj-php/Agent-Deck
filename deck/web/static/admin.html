模型

上下文与自动压缩

聊天页那个「上下文 xx%」和自动压缩都按这个数算，照模型的官方文档填 （DeepSeek V3 是 64K / 128K，官方长上下文版才到 1M；填错了只影响压得早晚）。
历史用到窗口的 80%（config.py 里的 CONTEXT_COMPRESS_AT）时，助手会把较早那段聊过的内容交给模型压成 一段摘要，只留最近几条原文，免得请求被模型以「超长」直接拒掉。 压缩用的就是上面那个聊天模型。
填大了比填小了危险：填大了会把压缩推迟到模型真正吃不下的时候，那一轮直接被 拒绝；填小了只是压得早一点、多花一次摘要的钱。 改完立刻生效，不用重启。

工具开关

工具是多轮对话里的「手」。用不上的组关掉，模型就不会乱调、也省 token。 关掉之后模型看不到这些工具的定义，硬调也会被拦。
基础组建议别关（读写文件、发表情包都靠它）。改完下一轮对话立刻生效。

系统提示词（人设）

这就是助手的人设：每个新会话历史里的第一条，决定她怎么说话、守哪些规矩。
框里显示的是当前生效的那份——没改过就是 config.py 里内置的那份。 改完点保存，新开的会话立刻就是新的，不用重启服务； 已经在聊的会话还留着旧的（那条消息在开会话时就定下来了，想让老会话换人设得点「新会话」）。
改过的存在 admin.json 里（不进 git），所以更新代码不会把它冲掉； 想回到内置的就点「恢复内置的」。

改的时候留意这几条（内置那份里标着「【重要】」的）：
助手每轮回复至少要发一张表情包（send_sticker）；代码要完整写进回答， 不能只丢在 workspace 里；workspace 只是临时测试区，跑完要把自己写的临时文件删掉；
数学式子不许用 LaTeX 源码；写代码只准碰 workspace 里的东西；去知识库查过要带上出处文件名。
删掉这些规矩助手就真会照做——所以改之前建议先把内置那份复制出来备份。

向量模型（知识库检索用，可选）

这是给知识库检索用的，跟上面聊天 / 图片那两套没关系。
检索是三路一起用的：原查询词匹配管精确词（STM32F103、I2C、IEEE754 这种）； 英文检索词会把中文问题翻成英文关键词去查英文教材（用上面那个「检索翻译模型」）； 向量管语义——换个说法、近义表达只有它认得出。
前两路不要钱，所以这一路留空也能用，配上只是更准。
最上面那个开关是总闸：关掉就彻底不用这一路（连配好的 key 也不调）； 开着但模型 / 地址 / key 没配齐，一样用不了。
任何 OpenAI 兼容的 /embeddings 接口都能用。
索引维度按 EMBED_DIM 校验（当前 ? 维）， 对不上会直接报错。改完要重启服务才生效（开关也算），而且会重新向量化一遍全库。
「单条输入上限」是给小块模型的：分块本来是按字数切的（500 字），跟你这个 向量模型能吃多长没关系。中文 500 字差不多 400~600 token，碰上 512 / 256 / 128 窗口的小模型就会超——轻则被它静默截断（块尾巴永远搜不到、还不报错），重则整个 接口 400、向量那一路直接关掉。留空就自动探测一次（发两条比它自己报的用量， 探得出来按它收口，探不出来按不限），也可以自己填。改了得重建索引，下面会显示用了多少。

向量库状态（每 5 秒自动刷新）：还没开始建…

怎么算建好了：上面那行写到「全部 N 块都带向量 —— 向量检索已生效」就是成了。 还在建的时候会显示进度（文件 x/y、已切多少块、已算多少块向量、当前在处理哪个文件、 发了多少次请求 / 重试多少次）。
中途被限流掐断会写明「还有 N 块没有」，重启服务会接着没算完的往下走—— 已经算好的文件都在 .cache/ 里，不会重来、也不白花第二遍钱。 限流（429）本身会自己多试几次：优先听接口的 Retry-After， 没给就 1.5 秒起指数退避（最多等 60 秒），普通失败试 3 次、限流试 6 次。
建库慢不慢，基本看对方接口的脸色：全库 8.5 万块，一次带 64 行就是 1328 次请求，接口一次要几秒到几十秒，全程就是几十分钟到十几个小时。嫌慢可以在 .env 里调 EMBED_BATCH（一次带几行，默认 64，接口嫌多会自动砍半）、 EMBED_WORKERS（并发几路，默认 8，被限流就调小）、 EMBED_TIMEOUT（单次等几秒，默认 60）。上面那行会写出已经跑了多久、多少块/秒， 照着这个数就能判断是接口慢还是自己这边慢。

批量导入（zip 压缩包）

压缩包里的文件名规则：心情 + 序号 + 后缀，例如 happy1.gif、love_02.png、think-3.webp。 去掉后缀后开头那串字母就是心情，后面的数字随便写（只影响显示顺序）。
心情只能是这八个：happy think confused proud cry angry sleepy love。
支持 png / jpg / gif / webp，gif 会动；单张不超过 8MB，一次最多 500 张。 认不出名字的会列在结果里告诉你，不会硬塞进某个心情。
压缩包可以带子目录（只看文件名），__MACOSX 和隐藏文件会跳过。

检查更新

更新就是在这个仓库里跑 git pull --ff-only：只在能快进时才动， 本地改过的东西一律不覆盖，也绝不 force。拉完会自动重启服务（systemctl）， 页面会断一下，刷新就好。
拉下来 ≠ 立刻生效：新代码要等进程重启才跑得起来。不是 systemd 管的话 它会告诉你「自己重启一下」——不重启的话，页面（静态文件）是新的、后端还是旧的， 会看到「接口 404」「数字对不上」这种怪事。重启完记得刷新页面， 浏览器可能还留着旧的前端文件。
要能从 Gitee / GitHub 拉，前提是这份部署本身是 git clone 出来的， 而且这台机器连得上那个站点。只 clone 了其中一个也没关系：仓库里找不到 对应厂家的 remote 时，会直接用 config.py 里那份镜像地址去拉 （只读，不改你本地的 remote 配置）。
你自己传的表情包和知识库文档不会被更新弄丢：它们都是没进 git 的新文件， pull 只动仓库里跟踪着的那批文件，碰不到它们。真正会被拦下来的是 「你手动删/改过仓库里自带的那批文件」——那种情况更新会拒绝快进并把原因写出来， 不会硬来。
